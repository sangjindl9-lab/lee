# 실제 연동 여부 · 미구현/미지원 · 출시 전 검토 항목

이 문서는 "무엇이 실제로 동작하고 무엇이 아닌지"를 그대로 적습니다.

## 1. 실제 연동 vs 샌드박스 구분표

| 영역 | 상태 | 설명 |
|---|---|---|
| 회원·상품·파일 보관·주문·납품·검수·분쟁·수수료·원장 | **실제 동작** | 실제 DB와 암호화 파일 저장소에 기록됩니다 |
| 결제 | **테스트 사업자만** | 내장 `sandbox`. 실제 돈이 이동하지 않습니다. 서명 웹훅·조회·취소·보류·지급·타임아웃을 흉내 내 플랫폼 로직을 검증하는 용도입니다 |
| 결제대금 보호(에스크로) | **미연동** | 어떤 실제 사업자와도 연동돼 있지 않습니다. 테스트 주문은 화면에 "테스트 결제 — 실제 대금 보호 없음"으로 표시됩니다 |
| 판매자 지급 | **테스트 사업자만** | 실결제 사업자에 대해서는 지급 API가 연동돼 있지 않아 "수동 지급(운영자 이체 후 증빙 기록)"으로 동작합니다 |
| 토스페이먼츠 어댑터(`src/providers/toss.js`) | **코드만 작성, 미검증** | 결제 승인·조회·취소만 구현. 공개 문서의 형식에 맞춰 작성했지만 실제 가맹점 키로 한 번도 호출해 보지 않았습니다. 대금 보류·지급대행·분쟁 시 지급 중지는 구현하지 않았고 기능 선언에서 `false`입니다 |
| 악성 파일 검사 | **선택 연동** | `CLAMSCAN_PATH`를 설정하면 ClamAV를 호출합니다. 미설정 시 모든 파일이 "검사 불가"로 표시됩니다. 이 개발 환경에는 ClamAV가 없어 실제 엔진 호출은 검증하지 못했습니다(EICAR 시험 서명 탐지는 내장) |
| 알림 | **사이트 내 알림만** | 이메일·문자·알림톡 발송은 연동돼 있지 않습니다 |
| AI 초안 | **선택 연동** | `ANTHROPIC_API_KEY`가 있을 때만 동작(Anthropic SDK). 이 환경에는 키가 없어 실제 호출은 검증하지 못했습니다. 키가 없어도 모든 거래 기능이 동작합니다 |
| 본인·사업자 확인, 계좌 실명 확인 | **미연동** | 운영자가 수동으로 확인합니다 |
| 세무(세금계산서·원천징수) | **계산과 기초 데이터만** | 과세 유형별 금액 계산, 원천징수 공제, 증빙 기초 데이터·CSV는 실제 동작. 세금계산서 발행, 원천세 신고, 지급명세서 제출은 연동돼 있지 않습니다 |
| PortOne V2 어댑터 | **없음** | 어댑터 계층(`src/providers/`)에 추가할 수 있는 구조이지만 작성하지 않았습니다 |
| 파일 저장소 | **로컬 암호화 디스크** | S3 호환 저장소·Presigned URL은 쓰지 않습니다. 서버가 주문 권한을 확인한 뒤 만료되는 1회용 링크로 복호화해 전송합니다 |

### 토스페이먼츠를 쓰려면 통과해야 하는 점검

1. 가맹 계약에서 docs/01 6절의 확인 항목을 문서로 확인하고 `/admin/pg`에 근거와 함께 기록
2. 테스트 키로: 결제창 → 성공 URL → 승인 → 주문 "결제 확인됨" / 금액 변조 시 승인 실패 / 전액·부분 취소 / 웹훅 수신 후 조회 반영 / 대사 실행 결과 0건
3. 웹훅 검증 방식(결제 상태 웹훅은 본문을 믿지 않고 결제 조회로 확인하도록 구현)이 현재 공식 문서와 일치하는지 확인
4. 대금 보호가 필요하면 사업자의 에스크로·지급대행 상품 계약 후 어댑터에 보류·지급·지급 조회를 추가 구현하고 필수 테스트(#8~#13)를 그 어댑터로 다시 실행

## 2. 미구현 · 미지원

| 항목 | 현재 동작 |
|---|---|
| 실제 PG의 대금 보류·자동 지급·분쟁 시 지급 중지 | 미구현. 확인표에서 미지원으로 처리되어 "보호 미적용", "수동 지급", "내부 정산만 보류"로 표시 |
| 가상계좌 입금 대기 흐름, 정기결제, 간편결제별 세부 처리 | 미구현 |
| 이미 지급한 금액의 자동 회수 | 미지원. 사후 환불·회수 검토(수동) 절차만 제공 |
| 사용자 코드의 자동 빌드·실행 검증(격리 실행 환경) | 미구현. 플랫폼은 업로드된 코드를 실행하지 않습니다. 운영자가 별도 격리 환경에서 확인한 결과를 "검증 범위 기록"으로 남기는 절차만 있습니다 |
| 7z·rar·ZIP64 내부 검사, 중첩 압축 내부 검사 | 미지원. "검사 불가"로 표시 |
| 이메일·문자 알림, 이메일 인증, 비밀번호 찾기 | 미구현 |
| 소셜 로그인, 본인인증 | 미구현 |
| 세금계산서·현금영수증 실제 발행, 원천세 신고·지급명세서 제출 | 미구현. 금액 계산·원천징수 공제·기초 데이터(CSV)까지만 |
| 지급명세서용 소득자 식별정보 수집 | 미구현(수집하지 않음) |
| 권장 스택(Next.js·TypeScript·PostgreSQL·Prisma·S3) | 현재 구현은 Express·JavaScript·SQLite·로컬 암호화 저장소입니다. `schema.prisma`는 없고 SQL 마이그레이션(`src/migrations/`)만 있습니다 |
| 전자서명·계약서 PDF | 미구현. 조건 해시와 동의 일시만 기록. 계약서 양식은 "법률 검토 전 초안" |
| 계약 중도 해지 정산, 변경 계약에서 기존 단계 내용 수정·삭제 | 미구현(단계 추가와 결제 전 단계의 금액·기간 변경만) |
| 기업 계정의 결재선·한도, 사업자 진위 확인 | 미구현(관리자 승인 1단계만) |
| 유지보수 계약 전용 상품(정기 과금) | 미구현. 의뢰 유형 "유지보수"와 지원 티켓으로 대체 |
| 업데이트 알림(구매자에게 새 버전 통지), 새 버전 재다운로드 권한 | 미구현. 기존 주문은 주문 시점 버전만 받습니다 |
| 이미지 업로드(상품 화면) | 미지원. 외부 https 이미지 주소만 입력 |
| 검색 엔진(전문 검색), 페이지네이션 | 단순 LIKE 검색, 목록 상한 고정 |
| 다중 인스턴스 운영 | 미지원(SQLite·메모리 기반 제한) |
| 마스터 키 교체 도구 | 미구현(키 ID만 기록) |
| 접근성 검수, 다국어 | 미수행 |

## 3. 출시 전 필요한 계약 · 정책 검토 항목

아래는 검토가 필요한 항목의 목록이며 법률 자문이 아닙니다. 전문가 확인이 필요합니다.

### 결제·정산 구조
- [ ] 플랫폼이 구매자 대금을 직접 받아 보관하지 않는 구조인지(PG의 지급대행·에스크로 이용) — 전자금융거래법상 등록 대상 여부
- [ ] 통신판매업 신고, 구매안전서비스(결제대금예치) 가입·표시 의무 적용 여부
- [ ] PG 계약: 디지털 상품·개발 용역 취급, 다수 판매자 구조, 최대 보류 기간, 자동확정, 분쟁 시 지급 중지, 부분 환불, 단계별 결제, 판매자 확인, 지급 후 환불 — docs/01 6절 전 항목
- [ ] 검수 기간(3~30일) + 분쟁 여유일이 PG 보류 한도 안에 들어오는지, 고액·장기 거래의 대체 절차
- [ ] 결제 비용 부담 주체와 실제 수수료율 반영(`pg_fee_bps`는 추정값)

### 약관·표시
- [ ] 이용약관, 판매자 약관, 개인정보 처리방침, 통신판매중개자 고지
- [ ] 디지털 콘텐츠의 청약철회 제한 요건(제공 개시 전 고지·동의, 시험 사용 제공 등)과 현재 "검수 후 확정" 절차의 정합성
- [ ] 자동확정 정책을 켤 경우 고지 문구와 기간
- [ ] 분쟁 결정·이의제기 절차의 약관 반영, 외부 분쟁조정 안내
- [ ] 환불 후 이용 종료·삭제 확인의 효력과 위반 시 조치
- [ ] 수수료 정책, 정산 주기, 정산 보류 사유의 판매자 고지

### 지식재산권
- [ ] 저작재산권 양도·이용허락 계약서 양식의 법률 검토(현재 "초안" 표시), 등록이 필요한 권리의 이전 등록 절차 안내
- [ ] 권리 침해 신고 처리 절차(통지·게시 중단·소명)와 플랫폼 책임 범위
- [ ] 오픈소스 라이선스 고지 의무에 대한 판매자 안내
- [ ] 비밀유지 조건 기본 문구의 법률 검토

### 개인정보·보안
- [ ] 개인정보 수집 항목·보유 기간, 탈퇴 후 거래 기록 보존 기간(전자상거래법상 보존 의무)과 `retention_days` 정합성
- [ ] 계좌번호 등 금융정보 암호화·접근 통제 기준 충족 여부, 마스터 키 보관(KMS) 정책
- [ ] 운영자 계정 발급·회수 절차, 접근 기록 점검 주기
- [ ] 외부 AI 전송 동의 문구와 전송 금지 자료 범위
- [ ] 침해 사고 대응·통지 절차, 백업 보관 위치와 복구 연습 주기
- [ ] 외부 보안 점검(모의해킹)

### 세무
- [ ] 플랫폼 수수료의 부가세 처리(`fee_vat_included` 설정)와 세금계산서 발행 주체
- [ ] 통신판매중개 구조에서 플랫폼이 사업소득 원천징수 의무자에 해당하는지(현재는 설정 `withholding_enabled`로 공제하도록 구현)
- [ ] 원천징수 세율·10원 미만 절사·소액부징수 기준(`withholding_min_tax`), 간이과세자 세금계산서 수수 기준
- [ ] 지급명세서 제출에 필요한 소득자 식별정보의 수집·보관 방식
