# 운영자 처리 매뉴얼

운영자 화면은 `/admin`입니다. 권한은 네 가지이며 한 사람이 여러 권한을 가질 수 있습니다.

| 권한 | 할 수 있는 일 |
|---|---|
| 심사(review) | 판매자 심사, 상품·파일 심사, 권리 매물 심사 |
| 고객지원(support) | 거래 조회, 분쟁, 신고, 지원 티켓, 검수 종료 심사 |
| 정산(settlement) | 지급, 환불, 대사, 수수료 정책 |
| 최고관리자(super) | 전부 + 결제 사업자 확인표, 운영 설정, 운영자 권한, 감사 기록, 이의제기 처리 |

상태를 바꾸는 모든 동작은 처리자·일시·내용과 함께 감사 기록에 남으며 수정·삭제할 수 없습니다.

## 1. 원칙

1. **화면의 상태 표시는 사실만.** 환불 "요청"과 "완료", 지급 "요청 접수"와 "완료", 내부 "정산 보류"와 사업자 "지급 보류"는 서로 다른 상태입니다. 고객 응대 시에도 구분해서 안내합니다.
2. **확인되지 않은 것을 보증하지 않습니다.** 파일 검사 통과, 실행 확인, 권리 자료 확인은 각각 별개이며 품질·권리 보증이 아닙니다. "검사 불가"를 통과로 안내하지 않습니다.
3. **결정에는 근거를 남깁니다.** 분쟁 결정, 검수 종료, 예외 승인, 수동 지급·환불은 근거 없이 저장되지 않습니다.
4. **환불·권리 분쟁의 판단은 사람이 합니다.** AI 초안 기능은 분쟁 처리 경로에 연결되어 있지 않습니다.

## 2. 판매자·상품 심사

- 판매자 심사는 등록 정보 확인입니다. 사업자 정보와 연락 가능 여부를 확인합니다.
- 상품 심사 확인 항목
  - 납품 파일이 상품 설명과 맞는 종류로 등록됐는가(소스 상품에 소스·설치 설명서가 있는가)
  - 항목별 파일 검사 결과. "문제 발견"은 원칙적으로 반려하고, 오탐이 분명할 때만 사유를 적어 예외 승인합니다
  - 포함·제외 범위, 권리 범위, 외부 유료 비용, 검수 기준이 구체적인가
  - 과장 표현("100% 안전", "모든 권리 검증" 등)이 없는가
- 직접 빌드·실행해 봤다면 **분리된 일회성 환경에서** 수행하고(운영 서버·운영 비밀키 접근 불가, 네트워크·시간·자원 제한), "검증 범위 기록"에 무엇을 어떤 환경에서 확인했는지 적습니다. 빌드 확인과 실행 확인은 따로 기록합니다.
- 판매 중 상품의 새 버전은 버전만 따로 심사합니다. 승인해도 기존 주문의 납품물은 바뀌지 않습니다.

## 3. 거래 모니터링 (`/admin/orders`)

| 필터 | 조치 |
|---|---|
| 파일 접근 실패 | 저장소 상태 확인 → "파일 접근 복구 재시도". 복구된 시점부터 검수 기간이 시작됩니다 |
| 납품 기한 초과 | 판매자에게 연락. 구매자가 문제 제기하면 분쟁 절차로 |
| 검수 기한 초과 / 검수 종료 심사 요청 | 구매자에게 알림이 갔는지, 다운로드 기록이 있는지, 열린 수정 요청이 없는지 확인 후 "검수 종료"(근거 필수) |
| 별도 확인 대기 | 고액·권리 양도 거래. 당사자·권리 자료·인도 목록을 확인하고 "별도 확인 완료" 기록 |

## 4. 분쟁 (`/admin/disputes`)

1. 접수 내용, 주문 시점에 고정된 조건, 양측 진술·증빙, 다운로드 기록, 메시지 기록을 봅니다.
2. **정산 보류 상태 두 줄을 확인합니다.** 외부 지급 보류가 "실패" 또는 "미지원"이면 사업자 쪽에서 지급이 나갈 수 있는지 정산 담당자와 확인합니다.
3. 같은 상품·판매자의 다른 주문("유사 피해 주문")을 보고, 필요하면 상품의 신규 판매를 제한합니다.
4. 당사자 합의를 먼저 유도하고, 합의가 안 되면 결정합니다: 전액 환불 / 부분 환불 / 거래 재개 / 판매자 정산 / 외부 절차 안내.
5. 결정 근거는 계약 기준(포함·제외 범위, 검수 기준, 지원 환경) 중 무엇에 따른 것인지 적습니다.
6. 결정 후 이의제기 기간(기본 7일) 동안 판매자 지급이 보류됩니다. 이의제기 건은 최고관리자가 처리합니다.
7. **이미 정산된 거래**는 지급 보류 대상이 아닙니다. "사후 환불·회수 검토"로 표시되며, 판매자와의 회수 협의와 구매자 환불 방법을 정한 뒤 환불 화면에서 결과를 기록합니다.

판단 기준 예시

| 상황 | 방향 |
|---|---|
| 소스 제공 조건인데 소스 없음, 필수 파일 누락 | 재납품 요구(거래 재개) 또는 환불 |
| 약속한 환경에서 실행 불가(구매자 재현 자료 있음) | 수정 후 재개, 불가하면 환불 |
| 계약에 없는 기능 요구 | 범위 외로 안내, 추가 개발 견적·변경 계약으로 연결. 판매자 정산 |
| 구매자 환경이 고지된 지원 환경과 다름 | 판매자 정산 방향, 근거로 지원 환경 조항 인용 |
| 소스를 받은 뒤 사유 없는 환불 요구 | 기각. 환불하는 경우에도 원격 삭제는 불가능함을 양측에 안내 |
| 권리 침해 신고 | 신고자 자료 확인, 판매자 소명 요청, 신규 판매 제한. 권리 귀속의 최종 판단은 외부 절차 안내 |

## 5. 환불 (`/admin/refunds`)

- 환불은 분쟁 결정 또는 양측 합의로만 실행됩니다. 실행하면 "처리 중"이 되고, 결제 사업자의 취소 성공이 확인돼야 "완료"가 됩니다.
- "처리 중"이 오래 남으면 "사업자에 재확인". "실패"는 사업자 거절 사유를 확인한 뒤 "환불 다시 요청".
- "수동 처리 필요"는 두 경우입니다.
  - 결제수단이 부분 취소 미지원: 전액 취소 후 재결제 또는 계좌 환불 등 대체 절차로 처리하고 증빙을 기록
  - 이미 지급된 거래: 회수 검토 결과와 환불 방법을 기록
- 수동 환불은 사업자 장부와 어긋날 수 있으므로 대사 화면에 검토 항목으로 남습니다.
- 전액 환불이 완료되면 추가 다운로드가 차단되고 구매자에게 이용 종료·삭제 확인을 요청합니다. **이미 받은 파일은 회수할 수 없다**고 판매자에게 안내합니다.

## 6. 정산 (`/admin/payouts`)

지급 요청 전에 시스템이 확인하는 조건: 결제 확인, 납품 완료, 검수 종료, 분쟁 없음, 환불 절차 없음, 별도 확인 완료, 이의제기 기간 경과, 판매자 승인 상태, 정산 계좌(변경 후 보류 기간 경과), 중복 지급 아님, 지급할 금액 있음. 주문 상세의 "정산 조건 확인"에서 남은 사유를 볼 수 있습니다.

| 상태 | 의미와 조치 |
|---|---|
| 지급 요청 접수 | 사업자가 접수함. 완료가 아닙니다. 주기 작업이 조회로 확정합니다 |
| 결과 확인 중 | 사업자 응답이 불명확했음. **수동으로 다시 요청하지 않습니다.** 시스템이 조회 후 기록이 없을 때만 같은 멱등 키로 재시도합니다. 5회 넘게 미확정이면 사업자에 직접 문의 |
| 수동 지급 대기 | 지급 API가 연동되지 않은 사업자. 계좌 확인(조회가 감사 기록에 남음) → 이체 → 증빙(이체일시·거래번호) 기록 |
| 실패 | 사유 확인 후 조건이 맞으면 다음 주기에 다시 요청됩니다 |

## 7. 대사 (`/admin/reconcile`)

| 불일치 | 의미 | 조치 |
|---|---|---|
| amount_mismatch | 결제 금액이 주문과 다름 | 접근 권한이 발급되지 않습니다. 사업자 확인 후 취소·재결제 |
| refund_mismatch | 사업자 환불액 ≠ 내부 환불액 | 사업자 쪽 직접 취소 여부 확인. 내부에 수동 환불 기록 |
| payout_mismatch | 사업자 지급액 ≠ 내부 지급액 | 이중 지급 여부 즉시 확인 |
| released_during_dispute | 분쟁 중인데 사업자가 지급함 | 사후 회수 검토로 전환 |
| protection_mismatch | 내부는 보류 중인데 사업자는 아님 | 주문의 보호 표시 정정 필요, 구매자 안내 |
| auto_confirm_before_inspection | 사업자 자동확정이 검수 종료보다 빠름 | 사업자 설정·확인표 재검토, 해당 상품 결제 차단 확인 |
| ledger_* | 원장 불변식 위반 | 개발팀에 즉시 전달. 해당 주문 지급 중지 |

## 8. 결제 사업자 확인표와 실결제 전환 (`/admin/pg`)

- 항목마다 계약서·공식 문서·사업자 답변으로 확인한 뒤 상태(지원/미지원), 값, 근거를 기록합니다.
- 확인되지 않은 항목에 의존하는 기능은 자동으로 꺼집니다(대체 절차는 docs/01 6절).
- 실결제 모드는 필수 항목이 모두 "지원"일 때만 켤 수 있습니다.
- 자동확정(`auto_confirm_enabled`)은 사업자 정책과 운영 정책 검토를 마친 뒤에만 켭니다.

## 9. 장애 대응

| 상황 | 대응 |
|---|---|
| 결제했는데 주문이 "결제 확인 대기" | 대사 실행(웹훅 유실 복구). 그래도 대기면 사업자 상태 확인 |
| 파일 저장소 장애 | 복구 후 "파일 접근 복구 재시도". 검수 기간은 복구 시점부터 |
| 사업자 장애로 지급·환불 불명확 | 기다립니다. 주기 작업이 조회로 확정합니다. 수동 재요청 금지 |
| DB 복구 후 | 대사 실행, 불일치 전건 확인 전까지 지급 주기 실행 보류(`settlement_cycle`을 weekly로 두고 수동 확인) |
| 마스터 키 유출 의심 | 서비스 중지, 새 키로 전체 파일 재암호화(별도 작업 필요), 판매자 고지 |
